# API Reference

The local API base URL is `http://localhost:8080`. Start the service with `./run.sh` (Bash) or `./run.ps1` (PowerShell), then use the examples below.

## `GET /health`

Check that the HTTP server is responding.

### Example

```powershell
Invoke-RestMethod http://localhost:8080/health
```

```bash
curl -i http://localhost:8080/health
```

### Success response

`200 OK`, plain text:

```text
ok
```

## `POST /documents`

Create a document. The service stores the document and splits its content into chunks in the same database transaction. Chunk text is not included in the API response.

### Request

Content type: `application/json`

| Field | Type | Required by current handler | Description |
| --- | --- | --- | --- |
| `title` | string | No | Document title. |
| `content` | string | No | Full document text to store and split into chunks. |

The handler currently checks that the body is valid JSON, but does not validate that either field is non-empty.

### PowerShell example

```powershell
$body = @{
    title = "Customer onboarding guide"
    content = "This document explains the onboarding process for new clients."
} | ConvertTo-Json

Invoke-RestMethod `
    -Method Post `
    -Uri http://localhost:8080/documents `
    -ContentType "application/json" `
    -Body $body
```

### curl example

```bash
curl -i -X POST http://localhost:8080/documents \
  -H "Content-Type: application/json" \
  -d '{"title":"Customer onboarding guide","content":"This document explains the onboarding process for new clients."}'
```

### Success response

`201 Created`, JSON:

```json
{
  "message": "Document created successfully",
  "id": 1
}
```

The ID is generated by PostgreSQL and will differ from the example.

### Errors

- `400 Bad Request` with plain-text `Invalid request body` if the request body is not valid JSON or cannot be read.
- `500 Internal Server Error` with plain-text `Failed to create document` if document or chunk persistence fails.

## `GET /documents`

List all documents, newest ID first. The current endpoint does not support pagination or filtering.

### Examples

```powershell
Invoke-RestMethod http://localhost:8080/documents
```

```bash
curl -i http://localhost:8080/documents
```

### Success response

`200 OK`, JSON:

```json
{
  "documents": [
    {
      "id": 1,
      "title": "Customer onboarding guide",
      "content": "This document explains the onboarding process for new clients."
    }
  ]
}
```

When there are no documents, `documents` is an empty array.

### Error

- `500 Internal Server Error` with plain-text `Failed to list documents` if the database query fails.

## `GET /documents/{id}`

Fetch one document by its numeric database ID.

### Examples

```powershell
$id = 1
Invoke-RestMethod "http://localhost:8080/documents/$id"
```

```bash
curl -i http://localhost:8080/documents/1
```

### Success response

`200 OK`, JSON:

```json
{
  "document": {
    "id": 1,
    "title": "Customer onboarding guide",
    "content": "This document explains the onboarding process for new clients."
  }
}
```

### Errors

- `404 Not Found` with plain-text `Document not found` if no document has that ID.
- `500 Internal Server Error` with plain-text `Failed to get document` if the database lookup fails for another reason.

## Chunking configuration

The API creates chunks when a document is created. Configure these values in `.env` before starting the service:

```env
DOCUMENT_CHUNK_SIZE=1000
DOCUMENT_CHUNK_OVERLAP=150
```

Chunk size and overlap are measured in Unicode code points by the current splitter. Overlap must be at least `0` and less than the chunk size. Invalid chunking settings cause the splitter to return no chunks; the document itself can still be created.

To inspect stored chunks in the local PostgreSQL container:

```powershell
docker exec crm-ai-postgres psql -U postgres -d crm_ai_assistant -c "SELECT document_id, chunk_index, content FROM document_chunks ORDER BY document_id, chunk_index;"
```
